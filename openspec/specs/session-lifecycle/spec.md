# session-lifecycle Specification

## Purpose
Allows starting new sessions and resuming ended sessions from the app, always inside tmux.

## Requirements

### Requirement: New session
`session.start` SHALL open a tmux window in the `claude-remote` session running the profile's launcher in the given `cwd` and reply with `session.started` carrying the created pane's `paneId` and, when it resolves in time, the new session's `sessionId`. With a `model`, the daemon SHALL pass `--model <id>` to the launcher. A nonexistent directory MUST produce `error` `invalid_cwd`. When the pane is gone shortly after the launcher returns (the agent CLI exited), the daemon MUST reply `error` `internal` naming the profile's actual agent (e.g. "Codex", "Claude Code") instead of `session.started`. After confirming the pane is alive, the daemon SHALL wait, up to a bounded timeout, for that pane's `SessionStart` hook to register a session; `sessionId` is that session's id, or `null` when the hook has not fired by the end of the wait — `session.started` is still sent, not delayed further. Every `session.start` MUST be logged by the daemon: accepted starts with the profile and pane, rejected ones with the error code and reason.

#### Scenario: Start in a project
- **WHEN** the app requests a new session on `drclaude` in the `~/workspaces/api` directory
- **THEN** a window is created and the session appears in the list after `SessionStart`

#### Scenario: Start with a model
- **WHEN** the app requests a new session with `model` `anthropic/claude-opus-5.5`
- **THEN** the launcher receives `--model anthropic/claude-opus-5.5`

#### Scenario: Claude Code exits right away
- **WHEN** the launcher creates the window but Claude Code exits before the settle check
- **THEN** the daemon replies `error` `internal` explaining that Claude Code exited and logs the rejection

#### Scenario: Codex exits right away
- **WHEN** the launcher creates the window for a Codex profile but `codex` exits before the settle check
- **THEN** the daemon replies `error` `internal` explaining that Codex exited (not "Claude Code") and logs the rejection

#### Scenario: Rejected start is logged
- **WHEN** `session.start` is rejected with `invalid_cwd`
- **THEN** the daemon log has a warning with the code and reason

#### Scenario: Session registers before the wait ends
- **WHEN** the new pane's `SessionStart` hook registers the session while `session.start` is still waiting
- **THEN** `session.started` carries that `sessionId` instead of waiting out the rest of the timeout

#### Scenario: Session has not registered yet
- **WHEN** the wait window elapses with no `SessionStart` hook for the launched pane
- **THEN** `session.started` carries `sessionId: null` and the pane keeps starting; a later `SessionStart` for it still updates the session list normally

### Requirement: Resume session
`session.resume` SHALL open a window with `claude --resume <sessionId>` in the session's original `cwd` with the correct profile.

#### Scenario: Resume an ended session
- **WHEN** the app taps "Resume" on an ended session
- **THEN** the session becomes controllable again with the same history

### Requirement: Recent directories
`projects.list { profileId }` SHALL return the `cwd` values of the profile's sessions ordered by most recent use, up to 30, each with `lastUsedAt`, the `branch` of the most recent session in that directory (`null` when unknown or outside git) and `sessions`, the number of the profile's sessions in that directory updated in the last 7 days.

#### Scenario: Choose a directory
- **WHEN** the user opens "New session"
- **THEN** they see the recent directories of the chosen profile, with branch and weekly usage when known

#### Scenario: Weekly count
- **WHEN** a directory had three sessions, one of them a month ago
- **THEN** its item reports `sessions: 2`

### Requirement: Checkout inspection
`checkout.inspect { profileId, cwd }` SHALL validate the directory like `session.start` (`invalid_cwd`) and reply `checkout.info { checkout, peers }`, where `peers` are the live sessions (controllable and not ended) whose checkout root equals the directory's, with id and title.

#### Scenario: Busy checkout
- **WHEN** the app inspects `~/work/api` while a live session works in `~/work/api`
- **THEN** the reply lists that session in `peers`

#### Scenario: Directory outside git
- **WHEN** the app inspects a directory that is not in a git checkout
- **THEN** the reply has `checkout` `null` and no peers

### Requirement: Start in a worktree
`session.start` SHALL accept `worktree: true`, which runs Claude Code with `--worktree <name>` so the session works in a new git worktree and branch of the directory's repository. The name MUST be generated by the daemon and be valid as a branch and directory name: the slug of the session's `name` when one is given, with `-2` to `-9` appended when the worktree directory or its branch already exists, else `remote-<timestamp>`. A directory outside a git checkout MUST produce `error` `bad_request`.

#### Scenario: Isolated start
- **WHEN** the app starts a session in `~/work/api` with `worktree: true`
- **THEN** Claude Code runs in `~/work/api/.claude/worktrees/remote-<timestamp>` on its own branch and the session has its own checkout

#### Scenario: Named isolated start
- **WHEN** the app starts a session named "Rate limit on login" with `worktree: true` and no worktree of that name exists
- **THEN** Claude Code runs with `--worktree rate-limit-on-login`

#### Scenario: Name already used
- **WHEN** the branch `worktree-rate-limit-on-login` already exists
- **THEN** Claude Code runs with `--worktree rate-limit-on-login-2`

### Requirement: Shared checkout warning on start
The new-session screen SHALL inspect the chosen directory; for a git checkout it SHALL show the branch and offer "Isolated copy (git worktree)" with an agent-neutral hint ("The agent works on its own branch in .claude/worktrees…"), and when the checkout has live sessions it SHALL list them, add that the worktree keeps them apart, and ask for confirmation before starting in the same checkout. When the daemon does not support inspection, or the inspection does not answer within a few seconds of tapping start, the screen MUST start without the warning and MUST NOT offer the worktree option. From the tap until the start succeeds, fails or is cancelled, the start button MUST show progress and ignore further taps. Failures MUST be shown under the button as translated messages.

#### Scenario: Confirm a shared start
- **WHEN** the user starts a session in a checkout with a live session and the worktree option off
- **THEN** the app asks for confirmation, offering to start in a worktree instead

#### Scenario: Inspection does not answer
- **WHEN** the user taps start and the directory inspection does not answer within 3 seconds
- **THEN** the app sends `session.start` without the shared checkout warning

#### Scenario: Immediate feedback
- **WHEN** the user taps start
- **THEN** the button shows a spinner right away and a second tap does nothing

### Requirement: Directory listing
`directories.list { path, prefix?, hidden?, limit? }` SHALL validate `path` like `session.start` (`~` expanded; missing or outside the home folder → `error` `invalid_cwd`) and reply `directories.results { path, parent, home, items, truncated }`. `items` MUST contain only subdirectories (including symlinks to directories), each with `name`, absolute `path` and `git` (true when it contains `.git`), sorted case-insensitively by name. `prefix` MUST filter names by a case-insensitive start match. Names starting with `.` MUST be left out unless `hidden` is true. At most `limit` items (default 200, max 500) are returned, with `truncated` true when more matched. `parent` MUST be `null` when `path` is the home folder. A directory the daemon cannot read MUST produce `error` `invalid_cwd`.

#### Scenario: Complete a prefix
- **WHEN** the app lists `~` with prefix `doc` and the home has `Documents`, `docker` and `Desktop`
- **THEN** the reply has `docker` and `Documents`, in that order, and no `Desktop`

#### Scenario: Hidden folders
- **WHEN** the app lists `~` without `hidden` and the home has `.config` and `work`
- **THEN** the reply has only `work`; with `hidden` true it has both

#### Scenario: Outside home
- **WHEN** the app lists `/etc`
- **THEN** the daemon replies `error` `invalid_cwd`

#### Scenario: Git checkout marker
- **WHEN** a listed folder contains a `.git` directory or file
- **THEN** its item has `git` true

### Requirement: Directory autocomplete and folder picker
The new-session screen SHALL suggest the subfolders matching the typed directory while the field is focused, using `directories.list` on the directory part of the text and its last segment as the prefix, and tapping a suggestion MUST fill the field with that folder followed by `/`. A "Browse" button SHALL open a folder picker that starts at the typed directory (or the home folder when it is empty or invalid), lets the user enter folders, go up to the parent (never above the home folder), toggle hidden folders and choose the current folder, which fills the field. When the daemon answers `directories.list` with `unknown_type`, the screen MUST hide the suggestions and the "Browse" button.

#### Scenario: Suggest while typing
- **WHEN** the user types `~/Doc`
- **THEN** the screen suggests `Documents` and tapping it fills `~/Documents/` and suggests its subfolders

#### Scenario: Pick a folder
- **WHEN** the user opens "Browse", enters `work` and then `api`, and taps "Choose this folder"
- **THEN** the field contains `~/work/api`

#### Scenario: Older daemon
- **WHEN** the daemon does not know `directories.list`
- **THEN** no suggestions and no "Browse" button are shown, and typing the directory still works

### Requirement: Close session
`session.close { sessionId, worktree? }` SHALL end a controllable session gracefully: the daemon denies the session's pending permission requests, sends Escape, types `/exit` and Enter in its pane, and waits up to 10 seconds for the session to be `ended` or its pane to disappear. If the pane is still there after that, the daemon SHALL kill it, but only when the registry still maps that pane to this session. The session MUST end as read-only (`ended`, no pane), its transcript MUST be kept and it MUST remain resumable. The reply is an `ack` whose data says how it ended (`exited`, `killed` or `already`) and, when a worktree action was requested, its outcome. A read-only session MUST produce `error` `not_controllable`.

#### Scenario: Idle session
- **WHEN** the app closes an idle session and Claude Code exits on `/exit`
- **THEN** the session becomes `ended` within the timeout and the ack says `exited`

#### Scenario: Session that ignores /exit
- **WHEN** the session has not ended 10 seconds after `/exit`
- **THEN** the daemon kills its pane, marks it `ended` and the ack says `killed`

#### Scenario: Waiting session
- **WHEN** the session waits for a permission when it is closed
- **THEN** the pending request is denied first, so the agent is not left blocked in the hook

#### Scenario: Pane reused by another session
- **WHEN** the pane was taken over by a new session id before the timeout elapsed
- **THEN** the daemon does not kill it and reports the old session as `already` ended

### Requirement: Worktree cleanup
`worktree.inspect { sessionId }` SHALL reply `worktree.info { worktree }`, where `worktree` is `null` unless the session's folder is inside a linked git worktree (never the repository's main checkout), and otherwise carries its `path`, `branch`, `mainRoot`, the number of modified or untracked files that are not ignored (`dirty`) and the number of commits reachable from HEAD and from no remote ref (`unpushed`). `worktree.cleanup { sessionId, action }` and the `worktree` option of `session.close` SHALL apply one action: `delete` only when the worktree is clean and pushed (otherwise `error` `bad_request`); `push-delete` commits any changes ("WIP from Remote Harness"), pushes the branch to `origin` creating the upstream when missing, then deletes; `discard-delete` removes the worktree and its branch without pushing. Before a removal that is not `discard-delete`, the daemon MUST inspect the worktree again and stop with `bad_request` if it has changes or unpushed commits. The removal MUST either complete or leave the worktree untouched: the daemon removes a stale lock (one whose process is not running, such as Claude Code's `claude session … (pid N …)` lock after the session ended), moves the whole folder out of place in one step, prunes the worktree entry, deletes the local branch when it is merged, and deletes the moved folder in the background with no time limit. Ignored files (such as `node_modules`) MUST NOT block a clean removal. Before cleaning up, the daemon SHALL wait up to 6 seconds for the process holding the worktree's lock (the agent leaving) to exit; when closing the session, if it is still running and the session's pane still exists (Claude Code's own "keep or remove the worktree?" dialog after `/exit`), the daemon SHALL end that pane and wait again. A worktree whose folder is already gone (Claude Code removes a clean worktree itself when it exits) SHALL count as removed after pruning its entry and deleting its merged branch. A lock still held by a running process MUST keep the worktree and report `error` `session_busy`, which the app shows as a translated message (the agent is still using the worktree; retry or keep it). A failed move or a failed push MUST keep the worktree and its branch and report `error` `internal` with the real reason (git's message, a timeout, an exit code or the file system error); every failure is also logged with the worktree path. Git MUST be called only from `infra/`.

#### Scenario: Clean worktree
- **WHEN** the app closes a session whose worktree has no changes and no unpushed commits with `worktree: "delete"`
- **THEN** the session ends and the worktree and its merged branch are removed

#### Scenario: Unpushed commits
- **WHEN** the worktree has 3 commits not on any remote and the user chooses push-delete
- **THEN** the daemon pushes the branch (creating the upstream) and then removes the worktree

#### Scenario: Push fails
- **WHEN** the push is rejected
- **THEN** the worktree stays, the branch stays, and the app shows git's error

#### Scenario: Main checkout
- **WHEN** the session runs in the repository's main checkout
- **THEN** `worktree.inspect` replies `null` and no cleanup is offered

#### Scenario: Large ignored folders
- **WHEN** a clean, merged worktree holds a `node_modules` folder that takes a minute to delete
- **THEN** the cleanup succeeds at once, the worktree is gone from `git worktree list`, the branch is deleted and the folder is deleted in the background

#### Scenario: Stale Claude Code lock
- **WHEN** the worktree is locked with `claude session remote-1 (pid 4242 start …)` and process 4242 is not running
- **THEN** the daemon unlocks and removes it

#### Scenario: Locked by a running process
- **WHEN** the lock names a process that is still running after the wait
- **THEN** nothing is removed and the daemon replies `session_busy` naming the process, which the app shows as "the agent is still using the worktree"

#### Scenario: Agent still in its exit dialog
- **WHEN** a session in a worktree with changes is closed with `push-delete`, and Claude Code stays in its "keep or remove the worktree?" dialog holding the lock
- **THEN** the daemon ends the pane, the lock's process exits, and the worktree is pushed and removed

#### Scenario: Agent removed the worktree itself
- **WHEN** Claude Code removed the clean worktree when it exited
- **THEN** the daemon prunes the entry, deletes the merged branch and reports the worktree deleted

#### Scenario: Move fails
- **WHEN** the worktree folder cannot be moved (for example "Operation not permitted")
- **THEN** every file of the worktree is still in place and the error carries the file system message

#### Scenario: Untracked file
- **WHEN** the worktree has one untracked file that is not ignored and the action is `delete`
- **THEN** the daemon replies `bad_request` and keeps the worktree

### Requirement: New session screen
The new-session screen SHALL be laid out as: an "Agent & profile" radio list, a Model row, the Directory field, the Recent list, the worktree toggle and the `Start session` primary button. Each profile row SHALL show the agent badge, the profile name in the profile color with the dashed `via <provider>` chip when the profile has a provider, `<agent> · <config dir>` (for example `Claude Code · ~/.claude`), and a selected mark on the chosen one. The Model row SHALL be shown only when the selected profile has a provider; it shows the chosen model, else the profile's default model, else "Provider default", and tapping it opens the model picker; the chosen model is sent as `model` in `session.start` and is reset when the profile changes. Each Recent row SHALL show the directory, its branch (`⎇`) and the number of sessions used there in the last 7 days when known, and the relative time of the last use. All texts MUST be translated.

The Recent list SHALL show at most three rows inline. A directory under `<repo>/.claude/worktrees/<name>` SHALL be folded into a row for `<repo>`, placed where the most recent of them would be, showing the number of worktrees folded into it ("3 worktrees") and the repository's own branch and weekly count when the repository itself is a recent directory. When the inline rows leave a recent directory out or fold a worktree into its repository, a "See all recent (N)" row SHALL follow, N being the number of recent directories; it opens a sheet listing every recent directory (worktrees as rows of their own) with a search box that filters by path and branch. Tapping a recent row, inline or in the sheet, SHALL fill the Directory field and close the keyboard (and the sheet).

The Directory field SHALL show the keyboard's Done key, which closes the keyboard. `Start session` and the starting indicator SHALL sit in a footer under the scrolling form, kept right above the on-screen keyboard while it is open, so they are visible without scrolling.

When the "Open the session after creating it" setting is on (its default) and `session.start` succeeds, the screen SHALL navigate straight into the new session (replacing the new-session screen with `/session/<id>`) and request focus on its message composer. When the reply's `sessionId` is `null`, the screen SHALL instead show a starting indicator naming the profile's agent and the directory (e.g. "Starting Claude Code in ~/project…") and keep watching the session list for a session whose `paneId` matches the one just launched, navigating in as soon as one appears. When the setting is off, `Start session` SHALL keep returning to the session list on success, as before. A failed start SHALL always leave the user on the form with the error, regardless of the setting.

#### Scenario: One Claude Code profile
- **WHEN** the computer has the profile "Personal" with config dir `~/.claude`
- **THEN** the list shows its row with the Claude Code badge, "Personal" and `Claude Code · ~/.claude`, selected, and no Model row

#### Scenario: OpenRouter profile selected
- **WHEN** the user selects the profile "Work" whose provider is OpenRouter with default model `anthropic/claude-sonnet-5.5`
- **THEN** its row shows the `via OpenRouter` chip, the Model row reads `anthropic/claude-sonnet-5.5`, and picking `anthropic/claude-opus-5.5` makes `Start session` send that model

#### Scenario: Recent directory details
- **WHEN** `~/projects/acme-api` was used by two sessions this week on branch `main`
- **THEN** its Recent row reads `⎇ main · 2 sessions this week`

#### Scenario: Many recent directories
- **WHEN** the profile has 20 recent directories and the screen is open on a small iPhone
- **THEN** three Recent rows and "See all recent (20)" are shown, and `Start session` is visible without scrolling

#### Scenario: Worktrees folded into their repository
- **WHEN** the recent directories are `~/acme/.claude/worktrees/fix-login`, `~/acme/.claude/worktrees/rate-limit`, `~/acme` and `~/blog`
- **THEN** the inline rows are `~/acme` with "2 worktrees" and `~/blog`, and the sheet lists all four

#### Scenario: Search the full list
- **WHEN** the user opens "See all recent" and types `blog`
- **THEN** only the directories whose path or branch contains `blog` remain, and tapping one fills the Directory field and closes the sheet

#### Scenario: Done key
- **WHEN** the user types a path in the Directory field and presses Done
- **THEN** the keyboard closes and `Start session` is visible

#### Scenario: Session already registered
- **WHEN** `Start session` is tapped, the setting is on, and `session.started` comes back with a `sessionId`
- **THEN** the screen is replaced by that session's conversation, composer focused

#### Scenario: Session still starting
- **WHEN** `session.started` comes back with `sessionId: null`
- **THEN** the screen shows the starting indicator, then navigates in once a session with the launched `paneId` appears in the list, composer focused

#### Scenario: Setting off
- **WHEN** the "Open the session after creating it" setting is off and `session.start` succeeds
- **THEN** the screen returns to the session list, as it did before this change

#### Scenario: Start fails
- **WHEN** `session.start` is rejected
- **THEN** the screen stays on the form showing the error, regardless of the setting

### Requirement: Session name at start
`session.start` SHALL accept an optional `name`, trimmed, on one line, without control characters and at most 80 characters; anything else MUST be rejected with `bad_request`. When the profile's agent supports a display name (Claude Code), the daemon SHALL pass `--name <name>` to the launcher as a single argument. For every agent, the daemon SHALL set the session's title to the name as soon as the session registers, including when it registers after `session.started`. Without `name`, the title rules are unchanged.

#### Scenario: Named session
- **WHEN** the app starts a Claude Code session with `name` "Rate limit on login"
- **THEN** the launcher receives `--name "Rate limit on login"` and the list shows that title before the first prompt

#### Scenario: Codex
- **WHEN** a Codex session is started with a name
- **THEN** no name flag is passed and the session's title in the app is still the name

#### Scenario: Invalid name
- **WHEN** `session.start` carries a name with a line break
- **THEN** the daemon replies `error` `bad_request`

### Requirement: Name field on the New session screen
The New session screen SHALL show an optional "Name" field under the directory, with chips that fill it: the directory's branch (except default branches) and up to three recent session names in that directory. The name SHALL be sent with whitespace collapsed to single spaces and cut at 80 characters, and only when not empty. All texts MUST be translated.

#### Scenario: Suggestions
- **WHEN** the directory is on branch `fix/login` and had a session titled "Rate limit on login"
- **THEN** the chips read `fix/login` and "Rate limit on login", and tapping one fills the field

### Requirement: What an isolated copy inherits
`checkout.info` SHALL carry `worktreeCopy` with `localSettings` (whether the checkout root has `.claude/settings.local.json`) and `include` (the entries of the root's `.worktreeinclude`, without comments and blank lines, at most 12; empty when the file is missing). The daemon MUST NOT copy files into worktrees itself: Claude Code shares or copies the local settings and copies the `.worktreeinclude` files when it creates the worktree. When the worktree toggle is shown, the New session screen SHALL list under it what the isolated copy inherits: "Local permissions" when `localSettings` is true, then the include entries; with no entries, it SHALL show a hint to list git-ignored files in `.worktreeinclude`. All texts MUST be translated.

#### Scenario: Project with local permissions and an include file
- **WHEN** the directory's checkout has `.claude/settings.local.json` and a `.worktreeinclude` with `.env` and `# comment`
- **THEN** `checkout.info.worktreeCopy` is `{ localSettings: true, include: [".env"] }` and the screen lists local permissions and `.env` under the toggle

#### Scenario: No include file
- **WHEN** the checkout has no `.worktreeinclude`
- **THEN** the screen shows the hint to list git-ignored files in `.worktreeinclude`

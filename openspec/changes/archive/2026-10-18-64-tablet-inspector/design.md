## Context

`MasterDetailLayout` shows the session list beside the detail `Stack` from 680 pt (`useWidthClass`). The terminal is a route (`TerminalScreen` subscribes to pane frames), the subagents list and the session details are bottom sheets, and the shell listens to ⌘N, ⌘, and Esc; the composer to ⌘⏎. `keyboardToolbar` already tells a hardware keyboard apart from a software one by the keyboard height. The prototypes (`tablet-landscape.html`, `tablet-portrait.html`) fix the columns, the inspector tabs and the hints row.

## Decisions

- **Three layout classes from one width.** `getLayoutClass` returns `compact` (< 700), `regular` (700–1099) or `wide` (≥ 1100); `sidebarMode(layout, portrait)` and `inspectorMode(layout)` (pure, tested) turn that into `none | inline | overlay` for each pane, so `MasterDetailLayout` only composes panes and overlays. The compact/regular breakpoint moves from 680 to 700 to match the prototype; the iPad mini in portrait stays regular.
- **Overlay sidebar in portrait.** In `regular` portrait the list slides over the dimmed conversation; it opens on its own on the list route (so the empty detail is never a dead end) and closes when a session is picked. The ☰ button is the Stack's `headerLeft` in that mode.
- **The inspector is a pane, not a route.** `InspectorPane` renders beside the Stack (inline in `wide`, as a right overlay in `regular`, from a header button); it mounts `TerminalScreen` as is (its pane subscription works per connection), `SubagentRows` and `SessionDetailsList`, which are the bodies extracted from the existing sheets so phone and tablet share one implementation. `useInspectorStore` keeps open, tab and width; the width is clamped to 280–420 and changed by a `PanResponder` on the pane's edge.
- **Hints only tell the truth.** `keyboardHints(state, t)` (pure) lists the shortcuts the app really has; the row shows while a hardware keyboard is attached on a tablet (`hardwareKeyboard`: focused field with a keyboard shorter than a software one). Return-to-send uses the field's `submitBehavior` under the same condition, so phones and software keyboards keep the newline.
- **Shortcuts live in one hook.** `useSessionShortcuts(selectedSessionId, layout)` registers ⌘1–9, ⌘K, ⌘T, ⌘., ⌘⇧M, ⌘A and ⌘D with `react-native-key-command`, reading the stores at fire time (list order from `listSessions` with the saved sort and prefs; pending permissions from the permissions store). ⌘A / ⌘D are ignored while a text field is focused, so select-all keeps working; `cycleMode` never reaches `auto`, which needs its confirmation. ⌘K focuses the search through a tiny request counter the field subscribes to.
- Hover states already exist on rows; the long-press action sheet doubles as the context menu with a pointer.

## Context

The daemon reaches a session only through its tmux pane (`InputService`, `TmuxClient.sendKeys/sendLiteral`) and learns its end from the `SessionEnd` hook or the pane reconciliation (every 5 s). Pending permission requests block Claude Code inside the `PermissionRequest` hook until the broker answers. `GitClient` only resolves checkouts; worktrees are created by Claude Code's `--worktree` under `.claude/worktrees`. The list has no gestures; `SessionRow` navigates on press. The prototypes (`sessions-swipe-actions.html`, `close-session-worktree.html`) fix the sheet texts and outcomes.

## Goals / Non-Goals

**Goals:** a graceful, bounded close that never kills a pane that already belongs to another session; worktree deletion that never destroys uncommitted or unpushed work without an explicit choice; list actions that match messaging apps; per-device pins and hidden sessions; every decision rule as a tested pure function.

**Non-Goals:** closing sessions outside tmux (read-only ones are hidden instead); syncing pins/hidden across devices; iPad context menus (#159) and the tray's Close (#160), which reuse `session.close`; drag to reorder.

## Decisions

- **Close sequence** (`CloseService.close`, under the session's `KeyedMutex`): deny the session's pending requests through the broker (so the agent is not stuck in the hook), `Escape`, then `/exit` typed literally + Enter; poll every 500 ms up to `CLOSE_TIMEOUT_MS = 10_000` for the session to be `ended` or the pane to be gone; otherwise `tmux kill-pane` on the recorded pane, only if the store still maps that pane to this session. The result says how it ended (`exited`, `killed`, `already`). Read-only sessions get `not_controllable`.
- **Worktree identity.** `GitClient.worktreeInfo(dir)` runs `rev-parse --git-dir --git-common-dir --show-toplevel` and treats the directory as a linked worktree only when the git dir differs from the common dir (the main checkout is never a candidate); it returns the branch, `dirty` (lines of `status --porcelain`), `unpushed` (`rev-list --count HEAD --not --remotes`: commits reachable from HEAD and from no remote ref, which covers "no upstream" too) and the main checkout root (parent of the common dir). The daemon exposes it as `worktree.inspect { sessionId }` → `worktree.info { worktree | null }`.
- **Cleanup actions** (`WorktreeAction`): `delete` (only when `dirty === 0 && unpushed === 0`, else `bad_request`), `push-delete` (`add -A` + commit "WIP from Remote Harness" when dirty, then `push -u origin HEAD`; a failing push stops with `internal` and the worktree is kept), `discard-delete` (`worktree remove --force` and `branch -D`). After a successful push or a clean state the worktree is removed with `worktree remove` and the branch deleted with `branch -d` when it is fully merged (`-D` only for discard). `session.close { sessionId, worktree? }` runs the close first and the cleanup after; the ack carries both outcomes so the app can say "closed, worktree kept: push failed".
- **Pins and hidden** live in `useSessionPrefsStore` (SecureStore JSON `remote-harness.session-prefs`). `listSessions(sessions, filter, sort, prefs)` drops hidden sessions unless they are live again (`controllable && state !== 'ended'`, which also clears the flag), and puts pinned ones first within the chosen order.
- **Row gestures.** `SwipeableRow` wraps `SessionRow` with `ReanimatedSwipeable` (left actions Close + More, right actions Mute + Pin, `overshootLeft/Right` off, full-swipe threshold triggers the first action with `Haptics.impactAsync`); `SessionsScreen` keeps the ref of the open row and closes it when another opens or the list scrolls. Long press and the More action open `SessionActionsSheet`, whose items come from `sessionActions(session, { muted, pinned, hidden, worktree })` (pure, tested).
- **Close sheet.** `CloseSessionSheet` asks `worktree.inspect` when the session's folder is a worktree candidate (`isWorktreePath` or a checkout root different from the folder's repository is unknown, so simply always ask for live sessions in a checkout), then renders the prototype's copy: the stronger warning when the session is `running` or `waiting`, the checkbox "Also delete the worktree" with path and branch, the warning line with counts, and the buttons chosen by `closeOptions(info)` (pure): dirty → push / discard / keep; unpushed only → push / discard / keep; clean → delete / keep. Discard asks a second confirmation. The header menu's "Close session" opens the same sheet.
- **Protocol errors.** `not_controllable` (close on read-only), `bad_request` (cleanup on a non-worktree or a delete that would lose work), `internal` (git failures, with the message).

## Risks / Trade-offs

- `/exit` relies on the TUI accepting input; a session stuck in a native dialog falls back to the kill after 10 s, which Claude Code handles like a closed terminal (the transcript is already on disk).
- `push -u origin HEAD` assumes a remote named `origin`; without one the push fails and the worktree is kept, which the sheet explains.
- Hidden sessions can come back when they turn live again; a user who hides an ended session and resumes it from the computer will see it reappear, which is the desired behavior.

## Context

The app is installed from source (iOS) or as an APK from Releases (Android). The brand assets are generated by `apps/mobile/scripts/icons.mts` (sharp + opentype.js) from one mark. The docs site (#136) is rendered by the Worker from Markdown pages. Store submission needs texts per language, a privacy policy URL, a support URL, a feature graphic (Play) and the 1024 icon, besides the accounts and certificates only the owner can create.

## Decisions

1. **Listing texts as a typed catalog, like the UI catalogs.** `STORE_METADATA: Record<Locale, StoreListing>` in `apps/mobile/store/metadata.ts`: the type comes from the en-US entry, so pt-BR and es-ES cannot drift, and a Vitest test enforces the stores' limits (App Store: name 30, subtitle 30, keywords 100, promotional text 170, description 4000; Play: title 30, short description 80, full description 4000) and that the URLs are pages the site serves. Texts follow the agent-neutral copy rules and name no private project.

2. **fastlane layout generated, not hand-kept.** `scripts/store-metadata.mts` writes `store/fastlane/metadata/{ios,android}/<locale>/*.txt` from the catalog (`pnpm --filter @remote-harness/mobile store:metadata`). The tree is generated output, ignored by git: `fastlane deliver` / `supply` and `eas submit` read it, humans read the catalog.

3. **Feature graphic from the icons script.** `featureGraphicSvg()` reuses the banner's composition at 1024 × 500 (mark, name, tagline) and renders to `apps/mobile/store/feature-graphic.png`, committed like `docs/brand/og.png`; the 1024 store icon is `assets/icon.png` already.

4. **Privacy policy as a docs page.** `privacy` joins the docs slugs (after security), so it has the three languages, the switcher, the link check and a stable URL (`https://remoteharness.app/<lang>/docs/privacy/`, negotiated at `/docs/privacy/`). It states what the software collects (nothing), what stays on the devices, what leaves the machine and when (Tailscale, FCM and the relay, update checks, OpenRouter, the website's host and fonts), the permissions the app asks for, and how to contact. The landing footer links it.

5. **Migration note in troubleshooting.** A short section tells users of the development-signed builds what changes with the store build: different signature, pair again, push re-registers, delete the old build.

6. **What stays with the owner.** Enrollment, the App ID for the new bundle id (#83 decides it), the APNs `.p8` key (also for Firebase), App Store Connect and TestFlight, review notes and demo, nutrition labels and export compliance, Play Console, Play Integrity / App Check enforcement, screenshots in three languages, and finally the landing's app cards (#132). The issue carries this checklist and stays open as blocked.

## Alternatives rejected

- Keeping the texts as `.txt` files only: thirty-plus files with no parity or limit checks.
- `eas.json` submit profiles now: every field is an owner identifier (ASC app id, team, service account); placeholders would only mislead.

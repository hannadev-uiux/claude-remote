## Context

`36-live-status` built the Live Activity with `expo-widgets` + `@expo/ui/swift-ui`: props travel as JSON (FCM → APNs `content-state`), already translated, and the widget only lays them out. The daemon owns the status through a pure reducer (`reduceLiveStatus`) and a throttle (`planSend`); the app starts the activity and, while active, also updated it locally.

## Decisions

### Props
`LiveStatusProps` gains `host`, `session`, `path`, `recent: string[]`, `ago` (translated template with `{time}`), `changedAt` and `endedAt: number | null`. All have Zod defaults and the widget falls back on missing values, so payloads from older daemons still render. `recent` items are formatted by the daemon (`"Bash · running a command"`, `"… ×3"`), keeping the widget free of logic that needs translations.

### Reducer
`LiveStatus` gains `recent` (step + tool name + count, max 3, newest first, consecutive repeats merged), `changedAt` (set when `state` changes) and `endedAt` (set on `stop`/`end`). `reduceLiveStatus(status, event, now)` takes the time instead of each event carrying it. A new step changes `recent`, so it goes through the same 15 s throttle as the step.

### Host
`os.hostname()` without a trailing `.local`, sent in the live props and in `auth.ok.host` (optional; older daemons omit it and the app falls back to the profile name).

### Timer
Running: `Text` with `dateStyle: 'timer'` from `startedAt` (ticks without updates). Ended: a static `m:ss` / `h:mm:ss` string of `endedAt - startedAt`, formatted inside the widget function. The state counter is `Text` with `dateStyle: 'relative'` from `changedAt`, placed in the `ago` template.

### State border
`strokeBorder` with `shape: 'containerRelativeShape'` on the banner root, so the border follows the system's rounded corners; the background is tinted with the theme surface (`activityBackgroundTint`).

### App icon in the widget
The widget extension is a separate bundle without the app's asset catalog. A config plugin (after `expo-widgets`, which recreates `ios/ExpoWidgetsTarget` on every prebuild) writes `Assets.xcassets/LiveActivityIcon.imageset` there from `assets/live-activity-icon.png` (144 px, generated by `scripts/icons.mts`, small to stay within ActivityKit's image limits) and adds it to the extension's Resources build phase. The widget loads it with `Image assetName`.

### Local updates
Local updates from the app cannot know the latest steps and would wipe them. The app now updates the activity locally only when the daemon is not keeping it updated (no Firebase, no relay or an older daemon); when `live.register` succeeds, updates come only from the daemon.

## Risks / Trade-offs

- [Session title may hold prompt text] → explicit user choice, recorded in the spec; the folder and title only go to the user's own devices through FCM/APNs.
- [`containerRelativeShape` stroke] relies on the widget container shape; if a future iOS changes it the border still draws, only the corners may differ.

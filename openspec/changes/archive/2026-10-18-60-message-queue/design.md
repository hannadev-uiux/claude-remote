## Context

`InputService.sendText` pastes a prompt into the pane and presses Enter under the per-session mutex; `session.input` is handled by the input feature. Session state comes from hooks (`UserPromptSubmit` → `running`, `PermissionRequest` → `waiting`, `Stop` → `idle`, `SessionEnd` → `ended`) and `SessionStore.onChange` tells features about every change. `PermissionBroker.hasPending` says whether the agent is blocked on a permission. The prototype `conversation-queue.html` fixes the queue card and the `Hold: send now · ⌘⏎` hint.

## Decisions

- **The daemon decides, the app asks.** `session.input` carries `mode`: `now` keeps today's behaviour, `queue` always holds, `auto` holds while the session is busy (`running`, `waiting`, a permission pending or prompts already queued) and delivers right away otherwise. The reply says `sent` or `queued`, so the app clears the field in both cases. Deciding on the daemon avoids racing the app's mirror of the state.
- **One feature owns delivery.** `features/queue/` registers `session.input` and the `queue.*` messages and uses `InputService.sendText` (passed in by `main.ts`, as other features receive services); the input feature keeps `session.key`. The queue listens to `SessionStore.onChange` for idle transitions and session ends, and never imports other features.
- **Deliver on idle, one turn at a time.** When a session is `idle`, controllable and without pending permission, the head prompt is delivered after `QUEUE_SETTLE_MS` (600 ms, so the TUI prompt is back) and the state is re-checked after the settle. After a successful delivery the session is marked as awaiting its turn until it leaves `idle` (or `TURN_GRACE_MS` = 15 s pass), so status-line touches while still idle cannot push the next prompt before the first one registered.
- **Failures stop the line.** A delivery error (pane gone, attachment expired, too large) is stored on the prompt, which stays at the head; automatic delivery resumes only after the user edits it (clears the error), sends it now or removes it. `queue.sendNow` removes the prompt first and puts it back with the error if the paste fails; `queue.flush` sends every prompt in order and stops at the first error.
- **Persistence and replay.** `queue.json` (`0600`, atomic writes) holds every queued prompt; it is loaded after the sessions are restored, so prompts of sessions that ended meanwhile are dropped on the first `onSessionChange`. Clients get `session.queue` per session with prompts on connect, as pending permissions are replayed.
- **Interactive menus and the raw terminal.** The daemon cannot see a TUI menu; delivering only on the `Stop` → `idle` transition (never while `running`/`waiting`) keeps the paste on a real prompt. A menu opened by the user is their explicit action; the raw terminal shows what happens.
- **App.** `useQueueStore` mirrors `session.queue`; `willQueue(session, pending, queued)` (pure) drives the hint and the send button's accessibility label; `QueueCard` sits in the session footer above the composer with the permission card; editing uses a small sheet so attachments are kept.

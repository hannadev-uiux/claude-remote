How it works

Your phone, your machine, your network. Nothing in between.

Sessions run inside tmux. The agent reports what happens through its native hooks, a small daemon on the machine bridges both to the phone, and Tailscale keeps it all private.

📱

Your phone

Native iOS and Android app. Reads the conversation, answers permissions, sends prompts, keys, photos and voice. Push and live status, with no content inside.

WebSocket over Tailscaletoken-paired · only your devices
💻

Your machine

The remote-harness daemon: tails transcripts, drives tmux, receives the agent's hooks on 127.0.0.1. One line to install, a Login Item or systemd unit to keep running.

hooks + tmuxsend-keys · capture-pane
▣

Your agents, in tmux

One window per session, one alias per profile.

clpersonal → ~/.claudeclwork → ~/.claude-workcxcodex → ~/.codex
Install on the machine

One command. It checks tmux, git, ripgrep and Node, finds your agents and profiles, and installs the launchers.

Scan the QR code

The setup shows it at the end (or remote-harness pair). Both devices on the same tailnet, done.

Run your alias

work opens Claude Code in tmux with that profile. The session shows up on the phone, fully controllable.

Features

Everything the terminal shows, and the parts the terminal can't.

≡

One list, every agent

Sessions from all your profiles and agents, sorted by what moved last, with a "waiting for you" strip on top.

●

Live conversation

Markdown, thinking, tool calls, diffs and results, streamed as they happen and paginated back to the start.

⛨

Permissions from your pocket

Allow, deny or always allow. "Always" is written as a rule by the agent itself and undoable from the CLI.

⏎

Queue or send now

Line up follow-ups while the agent works; they go in order when the turn ends. Hold to send immediately, like Ctrl+Enter.

▣

Raw terminal

The tmux pane itself, for menus and anything the structured view doesn't cover, with a key bar for Esc, Ctrl+C, arrows and Tab.

⎇

Start, resume, close

New sessions in any folder, optionally in their own git worktree. Resume read-only ones. Close with worktree clean-up that never discards work silently.

◔

Live status

Lock screen and Dynamic Island on iOS, a silent notification on Android: state, step type and elapsed time, never the text.

⌥

Subagents, voice, photos

Follow subagents and background tasks, dictate prompts on-device, attach photos. Autocomplete for @files and /commands.

Privacy & security

The daemon is a remote shell, so it's locked down by default.

✓
Only on TailscaleThe WebSocket binds to the Tailscale interface and nothing else. No port on the internet, no relay server reading your sessions.
✓
Token pairingEvery connection presents a token kept in the Keychain (macOS), Secret Service (Linux) or SecureStore (phone). Rotate it any time.
✓
Content-free pushNotifications carry a title, a profile and a session id. The live status adds the session name and folder, nothing from the conversation.
✓
No bypassThe app never offers the agent's "bypass permissions" mode, or any equivalent. Edits to your dotfiles are merged, backed up and fully reversible.
✓
No telemetryNothing is sent anywhere unless you set up push through your own Firebase project or the relay.
✓
Open sourceMIT licensed, built in the open with OpenSpec. Read SECURITY.md to report a problem.

Docs & FAQ

Questions people ask first

The full guide lives at remoteharness.app/docs: getting started, using the app, the daemon CLI, security, troubleshooting.

Does it work away from home?

Yes. Tailscale connects your phone and your machine wherever they are, with no port forwarding. The machine must be awake; the docs cover sleep and lock settings.

Which agents are supported?

Claude Code today, with every profile (CLAUDE_CONFIG_DIR) in one list. Codex CLI is in beta; Kimi, Qwen Code and OpenRouter-backed profiles are on the roadmap.

Can it run my agent unsupervised?

Only as far as the agent's own permission modes allow. The app offers default, accept edits, plan and auto; it never offers bypass. Every permission still goes through you, from the phone or the machine.

What about sessions started outside tmux?

They still show up, read-only. Resume one from the phone and it reopens inside tmux, fully controllable.

Is there a cloud component?

No. Optional push goes through FCM (your Firebase project or the content-free relay). Everything else stays on your tailnet.

Does the daemon need a Mac?

No: macOS, Linux (systemd) and Windows through WSL2 are all supported. The app runs on iOS and Android.
